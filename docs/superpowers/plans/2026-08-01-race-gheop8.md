**Goal:** Maximiser le hashrate SHA256d de worker6 (T-Display-S3) : bench par chemin, chirurgie de la boucle SHA matérielle, mode headless, pari SIMD/PIE — chaque optimisation validée au chiffre.

**Tech Stack:** PlatformIO `espressif32@6.6.0` (arduino-esp32, IDF 4.4), ESP32-S3, périphérique SHA (registres `SHA_TEXT_BASE`/`SHA_H_BASE`), assembleur Xtensa/PIE (gnu as du toolchain), dashboard Next.js (`~/src/miner-dashboard`) pour la persistance des mesures.

### Task 5: Interleave — hasher en logiciel pendant les attentes moteur

Le vrai pipeline : les fenêtres `w1`+`w2` (mesurées en Task 3) sont du CPU gratuit. On y exécute des rounds de SHA logiciel d'un flux indépendant, par petits pas, au lieu de poller dans le vide.

**Files:**
- Modify: `src/mining.cpp` (machine à états de rounds SW + boucle d'attente coopérative)

**Interfaces:**
- Consumes: profil w1/w2 (Task 3). Si `w1+w2 < ~60 cycles/nonce` au profil, **cette task est annulée** (rien à récolter) — le noter et passer à la Task 6.
- Produces: `race_hashes_sw` supplémentaires générés par le cœur HW ; verdict chiffré.

- [ ] **Step 1: Attente coopérative**

Remplacer les deux `nerd_sha_hal_wait_idle()` de la boucle par :

```cpp
static inline void race_wait_idle_coop()
{
    //Poll the engine, but do useful SW hashing between polls: one SHA round
    //per iteration keeps poll latency ~20 cycles (fine vs a ~70-cycle op).
    while (REG_READ(SHA_BUSY_REG))
        race_sw_step();
}
```

- [ ] **Step 2: La machine à états `race_sw_step()`**

Un hasher SHA256d incrémental sur un job SW dédié (pris dans `s_job_request_list_sw`, comme `minerWorkerSw`), qui avance d'un round d'une compression par appel.
